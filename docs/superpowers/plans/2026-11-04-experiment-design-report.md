## 二、设计决策：被试间/被试内与轮次

### 2.1 结论

主实验采用**单轮、被试间**设计：每名被试只经历一个条件、只做一次决策。信念在消息前后各测一次，属于**同一轮内的重复测量**，但不构成处理条件的被试内交叉。

### 2.2 为什么不用被试内多轮

| 维度 | 单轮被试间 | 多轮被试内 |
|---|---|---|
| 承诺的性质 | 一次性、不可验证，承诺可信度是真实信号 | 多轮后承诺可被验证，被试会学习「承诺是否兑现」 |
| 历史效应 | 无 | 前轮结果影响后轮信念与行为，需区组、顺序平衡、聚类标准误 |
| 策略学习 | 无 | 存在，尤其固定角色时 |
| 功效 | 较弱，需要更大 N | 较强，但效应量被历史污染 |
| 与文献可比性 | Berg 等 (1995)、Charness & Dufwenberg (2006) 均为一次性 | 与 Dufwenberg et al. (2026) 的 20 轮区组结构可比 |

论文用 20 轮是为了估计承诺与惩罚随轮次的动态，不是为了提高功效。本项目的研究问题是「沟通方向是否影响信任」，单轮足以回答；引入多轮反而会把「一次性承诺」变成「可验证的重复承诺」，改变机制本身。

若必须做多轮，最低要求是：固定角色、每轮重新随机配对陌生人、轮间不反馈对方身份、随机抽取一轮支付、6–10 轮而非 20 轮、沟通条件按区组并平衡顺序。否则「承诺」的操纵会失效。

### 2.3 比被试内更该改的一点：条件随机化的层级

当前实现把条件写在 **session config** 里：一个场次只有一个条件。这带来三个问题：

1. 条件与场次、时段、到场人群完全混淆，标准误无法区分「处理效应」与「这一场的人不同」。
2. 课程场景通常一次只能凑一个 session，四个条件要开四场，成本不可行。
3. 同一场次内无法做到四格同时平衡。

建议改为**配对内随机分配**：每个配对独立抽取两个布尔值（A 是否可发意向、B 是否可发承诺），双方共享同一对条件，四格在一次 session 内同时存在；角色也显式随机并写入数据。

这仍然是「被试间」——每个人只经历一个条件、只做一次决策——但去掉了场次级混淆，也让一次 session 就能收集全部四格。

### 2.4 样本量

每格 40–60 人（合计 160–240）比较稳妥；每格 25 以下只能检出较大效应（约 0.5 SD 以上）。报告里不写精确功效数值，只给这一区间与依据，避免用错检验族参数。

### 2.5 对代码的影响

- 新增真实采集配置 `trust_random`：`creating_session` 内打乱被试、重建配对、随机角色、随机配对级条件；四个固定条件 config 保留，但只用于演示与教学。
- 新增字段 `pair_cell`（`none` / `b_to_a` / `a_to_b` / `both`）与 `role_randomized`，便于导出后核对平衡。

## 四、目标二：方法学补齐（代码层）

按「中等」力度，只做能落到代码、能被测试钉住、能写进报告的改动。

### 4.1 诚实承诺页（Pledge）

- 新增 `Pledge` 页，位置：`Introduction` → `ComprehensionCheck` → **`Pledge`** → `BeliefBefore` → 消息页……
- 两种角色都要勾选：投资者承诺「所发消息反映我的真实送出意向」，受托人承诺「所发消息反映我的真实返还意向」。
- 未勾选不得继续（`error_message` 拦截），与论文的 honesty pledge 对应。
- 无沟通组同样保留此页：承诺针对「后测问卷的回答」，避免被试因条件不同而接受不同的前置仪式。

### 4.2 承诺的二元编码（仅供报告与描述统计，不进入激励）

- `content.py` 新增 `is_promise(label)`：受托人消息强度 ≥ 2 记为 `1`（明确承诺返还一部分及以上），0–1 记为 `0`。
- 明确注释：这是**预设消息量表上的派生编码**，论文的 `Promise` 是自由文本的人工双编码，两者不可等同；报告中必须写清这一点。
- 新增 `promise` 派生字段（写入 `Player`，便于导出），并在报告中给出编码规则表。
- 纯函数单测覆盖五档消息的编码，以及「未知文案抛错」。

### 4.3 信念测量：保持前后两次 + 随机计奖

- 已实现，本次只做两件收尾：
  1. 在 README 与报告中明确「无消息组只测一次，计奖时点恒为 after」的缺失结构，避免分析时把 `*_before` 的空值当成 0。
  2. 在 `BeliefBefore`/`BeliefElicit` 页面固定提示「本次回答可能被抽中计奖」，前提是指导语已披露（现有 `Introduction` 已按条件分支披露，保留）。

### 4.4 事后情绪与操纵检查（问卷或实验末页）

- 新增实验末页 `PostRound`（放在 `Results` 之后、`survey` 之前）：
  - A 侧：`anger_intensity`（1–5，「B 的返还决定让你有多不满」）。
  - A 侧：`perceived_message`（1–5，「你如何评价 B 的承诺可信度」；无消息条件不问）。
  - B 侧：`perceived_intent`（1–5，「你如何评价 A 的送出意向」；无消息条件不问）。
- 这些是**操纵检查与机制辅助变量**，不参与报酬计算；单轮设计下不做「有/无消息更生气」的组内比较（论文的 `anger1_2` 需要组内对照，本设计无法复制，报告中说明理由）。
- 若问卷 app 已有一般信任、风险偏好、独裁者博弈，则 `PostRound` 放在 `trust_game` 末尾，避免与个体差异测量混在一起。

### 4.5 理解检验补一题

- 现有 3 题保留，新增 1 题：消息是否改变收益规则（正确答案：不改变，消息只提供信息）。
- 目的：排除「以为发消息能提高乘子」的误解，这是 cheap talk 设计最常见的失效点。
- `ComprehensionCheck` 的 `error_message`、尝试次数记录、机器人测试同步更新。

### 4.6 文案中性化复核

- 全文扫描「应该信/不该信」「最符合你的利益」一类引导性措辞，统一改为事实陈述（消息由谁撰写、是否代表实验方、是否影响收益）。

### 章节结构

1. **引言与研究问题**：信任博弈范式、沟通的作用、本研究的问题与贡献。
2. **理论背景与假设**：内疚厌恶（二阶信念路径）与守诺偏好两条竞争解释；导出 H1（承诺提高可信度）、H2（意向提高送出额）、H3（信念中介）。
3. **实验设计**：博弈与参数（禀赋 10、乘子 3、返还上限 30）；2×2 条件；预设消息量表（0–4）及其理由；单轮被试间设计；**随机化层级**（角色与条件在配对层随机，而非场次层，并说明理由）；配对、陌生人、单轮；支付规则（1 点 = 1 元 + 出场费 20 元）；每个条件的目标样本量与功效说明。
4. **测量与激励**：行为变量（`send_amount`、`return_amount`、`return_ratio`）；信念前后两次、随机计奖时点与 10 个百分点容差、`x = 0` 不发奖；诚实承诺；事后情绪；操纵检查；理解检验。
5. **实验流程**：页面序列表（逐页：角色/条件/等待页）、时序图、双方并发与等待机制、演示·单步工具。
6. **实现**：oTree 版本与目录结构；模型与字段表；条件判断的单一真值来源（`sends_message` / `receives_message` / `any_message`）；`creating_session` 与随机化；防呆测试清单（配置镜像、文案同源、计奖时点、空提交拦截）。
7. **有效性与局限**：预设消息替代自由文本的代价；单轮无法做组内愤怒比较；实验室效应与样本；与论文的差异总表。
8. **伦理与数据**：匿名、无欺骗、退出与同意、数据保存与去标识。
9. **结论**：本设计能回答什么、不能回答什么、后续扩展（多轮、自由文本 + 人工编码）。
10. **参考文献**：`thebibliography` 环境，格式与字号沿用 `proposal.tex`（`\footnotesize`、紧凑行距），正文每条至少被引用一次，不得出现「列了但没引」的条目。
